Personal Reflection

What I Learned

Working on the Grounding Organizational Cybersecurity Guidance with Retrieval-Augmented Generation activity showed me how a RAG pipeline actually works from end to end. Instead of letting a language model answer from general pretrained knowledge, we loaded three cybersecurity PDFs, split them into 297 chunks, converted them into embeddings with all-MiniLM-L6-v2, and stored them in ChromaDB for top-3 retrieval. I also ran into practical setup issues along the way, like getting a 404 error on llama-3.1-8b-instant so I had to switch to openai/gpt-oss-20b, plus LangChain and ChromaDB dependency conflicts in Colab that needed version pinning, and using getpass so the Groq API key would not be exposed in the notebook.

The hallucination stress-test was the part that made the experiment click for me. In Task 2, with temperature set to 0 and the explicit fallback rule enabled, asking about the Apollo 11 lunar mission triggered the exact fallback response. In Task 3, even after raising temperature to 1.0 and removing the fallback sentence, the model still refused to answer because the context-only instruction remained in the system prompt, though its wording became more natural. Seeing both runs retrieve the exact same cybersecurity chunks confirmed that retrieval and generation are separate controls, and that prompt boundaries matter just as much as the vector database.

Overall, this activity helped me understand that RAG is not an automatic fix for hallucinations on its own. Reliable domain-specific AI systems depend on good chunking, strict grounding instructions, conservative generation settings, secure API key handling, and repeatable environment setup. Testing out-of-domain questions directly instead of assuming the model will behave made the engineering side of LLMOps feel much more concrete.

Personal Reflection

What I Learned

Working on our WW-M2 Project Proposal with my groupmates in QuantumStack taught me how much a clear, narrow problem statement matters before building any AI system. Our first version proposed a RAG chatbot for general cybersecurity incident guidance among college students, covering phishing, suspicious links, passwords, and compromised accounts. That first version was rejected because it was a problem that is not specific and relevant enough, and the scale and scope can become so large that it would be difficult to manage properly in a student project.

Going back to revise the proposal pushed us to look for a real-world problem with tighter boundaries and clearer sources. That led to LendSuri, which focuses specifically on helping Filipino users check official Philippine SEC records for Online Lending Platforms instead of trying to cover general cybersecurity advice. By narrowing the knowledge base to a dated SEC OLP registry snapshot, the 2021 historical list, recent SEC advisories, MC No. 20 s. 2026, and official complaint procedures, we were able to define a measurable evaluation plan with around 30 test questions and choose Llama-SEA-LION-v3 8B-IT to support both English and Filipino queries.

Looking at Version 1 and the Final Version side by side makes it obvious why the rejection was helpful. The revised proposal is much more grounded, easier to test, and directly tied to a specific local issue where authoritative records actually exist. As a fourth-year student, this experience reminded me that scoping down a project early does not make it weaker; instead, it makes the system more realistic to build, evaluate, and defend.
